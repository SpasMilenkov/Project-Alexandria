The quickest way to run Alexandria is the Builder, an interactive terminal tool in the `Builder/` folder of the source checkout. It builds the application from your source code, generates secrets and a HTTPS certificate, starts the services you choose and checks that they work. This page is the short path. The [Builder guide](/guides/using-the-builder/) covers every screen, option and maintenance task.

<Aside type="caution">
Alexandria is pre-alpha. The Builder targets one Linux x64 machine (glibc) with a local Docker engine and was tested on Ubuntu 24.04. It refuses to run on other platforms. There is no published installer download or image registry release: you build from source.
</Aside>

## Before you start

You need:

- **A complete source checkout.** The Builder does not clone anything. For example, `git clone https://github.com/SpasMilenkov/Project-Alexandria`. Keep the checkout after installing, because the generated Compose file mounts some files from it.
- **Docker Engine and the `docker compose` plugin**, running locally and usable by your account. Remote Docker contexts are not supported.
- **The .NET 10 SDK**, to run the Builder from source. The first run restores its one NuGet package, so it needs network access.
- **A stable LAN IPv4 address or a DNS name** that every client resolves, plus a free TCP port for HTTPS (443 by default). IPv6 and `localhost` are not supported. Port 80 is optional and only forwards `http://` to HTTPS.
- **Room to build.** Image builds need access to image registries and package repositories. Lyrics lookup needs outbound HTTPS to `lrclib.net`.

The Builder checks these and explains any failure, but it does not install missing tools or change your firewall, router or any device's trust store.

### Resources

The system check measures what Docker can use. As a planning guide, the core stack needs about 4 GB of memory, and each feature adds to that.

| Selection | Allowance |
| --- | --- |
| Core stack | 4096 MB |
| Document previews | 1024 MB |
| Adaptive streaming | 1024 MB |
| Audio analysis (coordinator and one classifier) | 3072 MB |
| Lyrics | 512 MB |
| Monitoring | 1536 MB |

These include headroom and are not measured minimums. Aim for at least 2 CPU cores, or 4 with audio analysis, and at least 10 GB free on Docker's data filesystem.

## Install

<Steps>

1. Open a terminal in the repository root and start the Builder.

   ```bash
   dotnet run --project Builder/Builder.csproj
   ```

2. Choose **Set up Alexandria on this machine**, then work through the screens. Esc goes back and keeps your entries.

   | Screen | What you decide |
   | --- | --- |
   | Where to install | The source folder, and a separate settings folder for generated files. |
   | Features | Six toggles (media previews, document previews, adaptive streaming, automatic tagging, lyrics, monitoring) and an audio model: Off, Effnet or MAEST. |
   | System check | Nothing, unless a check fails. |
   | File storage | Garage store capacity in GB (default 10). |
   | Network access | LAN address or DNS name, and the HTTPS port. |
   | HTTPS certificate | Generate a local certificate authority, or import your own PEM files. |
   | Audio models | Use existing model files, or allow verified HTTPS downloads. Skipped when analysis is off. |
   | Your account | Administrator email, username and password. |

3. Review the summary. Nothing has been written yet. Press Enter to start the installation.

4. Wait for the build and checks to finish. The first run compiles every image and takes a while. If a stage fails, the screen offers retry, logs and container status. See the [Builder guide](/guides/using-the-builder/#if-a-stage-fails).

5. When the done screen shows the HTTPS address, note it, then press Enter. Alexandria keeps running after the Builder closes.

</Steps>

## What you end up with

In the settings folder you chose:

- `.env`, `docker-compose.yml`, `garage.toml` and the proxy, broker and certificate files, generated for your choices.
- `INSTALLATION.txt`, with the exact HTTPS address, paths, project name, volume names and ready-made start, stop, status and log commands. It contains no passwords.
- `nginx/CLIENT-TRUST.txt`, with the certificate fingerprint and how to trust it on a device.
- `installer-logs/`, with one log per run.

Uploaded files and the database live in Docker-managed named volumes, outside the settings folder. Back up both: see [Operations, recovery and backups](/guides/operations/).

<Aside type="note">
A generated certificate is not trusted by other devices automatically. Before signing in from a phone or another computer, follow [First steps](/getting-started/first-steps/) to install the public certificate authority on each client.
</Aside>

## Changing or updating later

Run the Builder again and select the same settings folder, or pass it directly:

```bash
dotnet run --project Builder/Builder.csproj -- --settings '/absolute/path/to/settings'
```

It switches to repair mode, keeps your credentials, account, certificate authority and data, and lets you change features, the address or the certificate. To update Alexandria, pull the new source into your checkout, take a backup and run the Builder on the same folder. It rebuilds the images and runs all the checks again. Details are in [Re-running the Builder](/guides/using-the-builder/#re-running-the-builder).

Running Alexandria without the Builder is possible but separate: see [Manual Compose reference](/getting-started/manual-installation/). For contributor hot reload, see [Development setup](/guides/set-up-development-environment/).
