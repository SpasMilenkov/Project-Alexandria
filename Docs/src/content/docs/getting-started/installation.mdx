<Aside type="caution">
The installer currently covers **local self-hosted setups**. Server deployments are on the roadmap — until then, use the [manual installation](../manual-installation). Running on a private home network is recommended.
</Aside>

The Alexandria installer is an interactive TUI that sets up the whole stack on your machine: it asks what you want in plain language, creates every password for you, builds and starts all services with Docker, and even creates the secure storage keys automatically.

| Key | Action |
|---|---|
| `↑` `↓` | Move between options |
| `Space` | Toggle a feature on/off |
| `T` | Switch the installer's look (Papyrus ↔ Aurora) - saved instantly |
| `R` | On the summary: flip the memory chart between breakdown and bar |
| `A` | On the summary: see every component that will run |
| `Enter` | Confirm |
| `Esc` | Go back one step |
| `Ctrl+C` | Abort (cleans up running containers) |

<Aside type="tip">
**TL;DR**: Run the installer → choose features → pick a folder → confirm. No config files need to be edited by hand.
</Aside>

## Prerequisites

- **Docker** with **Docker Compose** (v2) — the installer checks this first and shows install instructions per OS if missing
- **2+ CPU cores** recommended
- **4 GB of memory** is comfortable for the default feature set; the installer estimates usage live based on your choices
- **10 GB free disk space**

## Running the Installer

From a checkout of the repository:

```bash
dotnet run --project Builder
```

<Steps>

1. **Pick how the installer looks** — Papyrus (warm gold) or Aurora (violet). A live preview of each is shown on first run; your choice is remembered for next time.
2. **Choose "Set up Alexandria on this machine"**.
3. **Toggle features** — every option explains what it does and what it costs before you decide.
4. **Create your sign-in account** — email, name, password. This becomes your Alexandria login; write it down.
5. **Choose where settings live** — the detected project folder is offered as the default; any other folder works too.
6. **Confirm the summary** — services count, memory estimate, address, and exactly which files will be created.
7. **Watch it run** — building, storage keys, service startup and health checks stream live. Nothing else to click unless something fails.

</Steps>

## Feature Toggles

| Toggle | Default | What it gives you |
|---|---|---|
| Media processing | On | Thumbnails, previews, clips |
| Document previews | On | PDF previews without opening downloads |
| Adaptive streaming | On | Big media starts instantly, adapts to connection quality (~1 GB) |
| Audio tagging – fast | On | Genre & mood recognized right after upload |
| Audio tagging – deep | Off | Richer tags, much slower and heavier (~2 GB) — best on stronger machines |
| Automatic tagging | On | Master switch; taggers only have effect when this is on |
| Lyrics fetching | On | Finds lyrics automatically |
| Monitoring dashboard | Off | Health graphs at localhost:3000 (~1 GB across several helpers) |

## Where Your Files Go

Everything generated lands in the folder you picked:

```
docker-compose.yml      how the services run
.env                    every setting and password - locked to your user only
garage.toml             storage configuration
alexandria-config.json  record of your choices
init-output/            temporary bootstrap files (cleaned up after setup)
prometheus/             monitoring config + its access token (when enabled)
```

<Aside type="caution">
`.env` holds every secret of your installation. The installer locks it to your user account; treat it like a password manager export. Storage keys are created inside the stack during setup and merged into `.env` automatically — no plaintext copies are left behind.
</Aside>

## Re-running the Installer

If the target folder already has an `.env`, your existing settings are kept and only missing values are filled in. Starting completely fresh requires typing `FRESH` to confirm; the old file is renamed (never deleted) so nothing is lost by accident.

## Post-Install Commands

From your install directory:

| Command | Purpose |
|---------|---------|
| `docker compose logs -f` | Stream logs from all services |
| `docker compose ps` | Check container status |
| `docker compose down` | Stop everything (data preserved) |
| `docker compose up -d` | Start everything again |

## Troubleshooting

### Setup failed at some phase

The installer shows which phase turned red. Pick **Show container status** on the failure screen, or:

```bash
docker compose logs garage-init   # storage key creation
docker compose logs rabbitmq      # messaging startup
```

If the storage key step reports an unreadable key file, do **not** delete `init-output/garage-credentials.env` — it contains the only copy of those keys. Fix or restore it and re-run the installer; it will merge the existing keys instead of starting over.

### Services still starting after the timeout

Large image pulls make the first boot slow. Check progress — services often finish on their own:

```bash
docker compose ps
```

### Port already in use

The installer checks ports 80/443 (and 3000 for monitoring) before installing and offers automatic fallbacks. If something started after that check:

```bash
lsof -i :80        # Linux / macOS
netstat -ano | findstr :80   # Windows
```

Stop the conflicting program or re-run the installer and accept a different port.
